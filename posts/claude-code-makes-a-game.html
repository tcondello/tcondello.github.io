Claude Code Makes a Game

Date: March 2026 Read: ~8 min Tags: Claude Code, SpacetimeDB, game dev

One of my favorite ways to size up a coding agent isn't running evals or reading benchmarks. It's asking it to build a game. This is because it is easy to see when it fails, meets or exceeds expectations.

Games are a useful test too because they force integration. A render loop, game state, input handling, enemy logic, and a UI that ties it together — all running as one coherent system. An agent that ships a working game has demonstrated something that a benchmark score can't: the ability to hold a design in mind and execute it across subsystems simultaneously.

01

Last Year: Dozens of Prompts, One Space Shooter

In 2024 I had Gemini build a space shooter. It took around a dozen prompts and some specific technical direction. The result was genuinely good it was able to produce a visually dynamic game with working mechanics and a ship that felt fun to fly. Now outside of the technical aspect if I just say how long I played the game for it was roughly a couple of minutes.

02

This Year: Three Prompts to Claude in the browser...

This year I wanted to see what had changed. So I began with some context questions

01 You know the game Asheron's Call
02 Do you know the game Vampire Survivors
03 smash the 2 together but keep the fantasy and ancient aesthetics

Just for fun I threw out the "smash the 2 together but keep the fantasy and ancient aesthetics."" To my surprise its reply was a working prototype of a game that combined the best of both worlds. So I thought well how far can I push it until the wheels fall off? Loot pools, enemy types, character building, Claude didnt even break a sweat.

So then I thought what else could I do?
03

Enter Claude Code

I gave Claude Code two things: the game HTML file and the integration guide markdown. All produced by Claude in the browser. Then I wanted to test out this new database I heard about for game dev called SpacetimeDB.

Claude Code then built a SpacetimeDB server module in TypeScript, wired up multiplayer using the SpacetimeDB browser WebSocket SDK, added server-authoritative combat, damage, health, and death all resolved server-side and gave each player persistent state across sessions.

The handoff worked because I was able to develop an MVP with claude to get the game mechanics working. Then I build an MVP with claude code and asked it to smash them together.

03

The Hand-off Document Pattern

Before ending a long session I would have Claude write a markdown file for how it would integrate the elements of the app it just built into a game.

Many times I would ask it to write a plan then ask me 3 questions to seek clarity of the plan and then give me the priority before I would let it go off and start building. This pattern worked well and also lead to very long runs. For example I had Claude Code "thinking" for over 25 minutes multiple times.

06

The Pixel Art Pipeline

Claude did a good job of building basic visuals but I wanted to see what it could do. I have tried in the past to make my own pixel art generators by hand from tutorials and using AI. I knew it wasnt easy, I was stunned at how Claude performed. I expected the basic templates but the animations thats what blew me away. It was so good I started to make the rarity system operate like a game pallet upgrade. From Gameboy to SNES to N64. Even this curveball it handled well.

Pixel Gear Forge — generates procedural equipment sprites. No only did the armor look different it even coded different pixel attack animaton for each weapon type Five rarity tiers, each at a different grid resolution: 10×10 for Game Boy (Common) up to 20×20 for N64 (Legendary).

Creature Lab — enemy sprite editor with palette variants for different enemy types and threat levels. With out asking it included damage and death animations. My daugher even enjoyed having it make Pink Unicorns that shot horns and left piles of glitter poops behind.

Boss Lab — larger-canvas boss designer it developed a unique animation for when the boss was enraged. For the hydra boss it had each head get its own dealth animation but also coded what it would look like if they grew back!

08

Takeaways

Capability moves fast

What took ~12 prompts and real steering in 2024 took 3 context-free prompts in 2025. That's not a rounding error — the bar moved. If you haven't stress-tested a model at something genuinely hard recently, your intuition about what they can do is probably stale.

The limiting factor has shifted

It's no longer "can the agent build this." It's knowing what to ask for, having the taste to recognize when something is working, and knowing when to stop adding systems before the complexity collapses on itself.

The hand-off document is underrated

Not just for AI context switches — for any handoff. A model narrating its own work is cheap to generate and often more precise than documentation written retrospectively by a human. It knows every decision it made.

Tool specialization matters

Claude in the browser is fast for single-file iteration — you see the result immediately and steer in real time. Claude Code handles multi-file projects and deployable artifacts better. Used in sequence with a clean handoff document, they complement each other in ways that neither covers alone.
